# Выпуск расширения

## Предварительная настройка

Репозиторий: https://github.com/oiv-an/ivol-project-catalog.
Идентификатор расширения: ivol.ivol-project-catalog. Не меняйте издателя при обновлении.

### Локальная публикация (проверенный способ)

Marketplace: используется Microsoft Entra ID через сохранённый вход Azure CLI, PAT не требуется. После входа `az login --allow-no-subscriptions` публикация готового пакета:

```sh
npx --yes --package=node@22 --package=@vscode/vsce@4.0.0 -- vsce publish --azure-credential --packagePath ./ivol-project-catalog-<version>.vsix
```

Open VSX: передайте сохранённый токен через OVSX_PAT только процессу ovsx. Не выводите токен и не передавайте его аргументом команды. Локальный приватный файл хранится вне репозитория; его расположение зафиксировано в локальных инструкциях сопровождающего.

Версия 0.6.1 принята обоими магазинами этим локальным способом. Первоначальные задания магазинов в GitHub Actions остановились без секретов; это не отменяет последующую успешную локальную загрузку.

### Разделение публикации и GitHub Actions

Публикация Marketplace и Open VSX выполняется только локально, по запросу пользователя, командами выше. GitHub Actions не повторяет загрузку в магазины: задания этих площадок удалены, чтобы не дублировать публикацию и не создавать ошибки из-за отсутствующих токенов.

Workflow Release сохраняет сборку пакета, контрольную сумму и создание GitHub Release. Для этого используется штатный токен GitHub; секреты магазинов в репозитории не требуются. Не переносите кэш Azure CLI и локальные токены в GitHub.

Не коммитьте токены. Для Open VSX владелец должен выполнить требования регистрации издателя и лицензионного соглашения. Авторизация GitHub сама по себе не даёт доступа к магазинам.

Официальная документация:
- https://code.visualstudio.com/api/working-with-extensions/publishing-extension
- https://github.com/eclipse/openvsx/wiki/Publishing-Extensions

## Локальная сборка

Для полного пакета требуются macOS с Apple Command Line Tools (Swift), Node.js/npm и интернет для загрузки упаковщика. Перед упаковкой автоматически собирается универсальное приложение macOS (Apple Silicon и Intel). Команда package использует Node.js 22 через npx и сначала проверяет синтаксис.

```sh
npm run package
```

Результат: ivol-project-catalog-<version>.vsix. Старые пакеты сохраняются локально и не входят в Git. В VSIX включены manifest, README, LICENSE, CHANGELOG, src, media и скомпилированный помощник native/macos/bin. Исходник помощника и скрипт сборки хранятся в репозитории; пользователю компилятор не нужен.

## Автоматический релиз

1. Обновите version в package.json и CHANGELOG.md. Проверяйте соответствие версии сообщениям интерфейса, если они изменялись.
2. Выполните npm run check, проверьте интерфейс в Extension Development Host и состав пакета.
3. Закоммитьте изменения в main и отправьте их на GitHub.
4. Создайте и отправьте тег v<version>, точно совпадающий с package.json.
5. Дождитесь workflow Release: GitHub Release с VSIX и SHA256SUMS.txt. Заданий публикации магазинов в нём нет.
6. По запросу пользователя опубликуйте проверенный пакет в Marketplace и Open VSX локальными командами выше, если он ещё не опубликован. Проверьте карточки магазинов: завершение загрузки не означает завершение проверки площадкой.

Ручной запуск Release допускается только на теге соответствующей версии. Успешную публикацию в магазинах не повторяйте. Старые запуски и теги содержат прежнюю конфигурацию с заданиями магазинов: их повторный запуск не применяет новое правило; для следующих релизов создавайте теги на коммитах с обновлённым workflow. Старые уведомления об ошибках не отменяют успешную локальную публикацию.

Check проверяет синтаксис и упаковку на push в main и pull request, без публикации и без секретов. Preview VSIX доступен в артефактах задания.

## Установка и ограничения

Установка вручную: VS Code → Extensions → Install from VSIX. Не перезагружайте рабочие окна автоматически. После установки обновления пользователь самостоятельно перезапускает окно.

Перед проверкой реального переноса используйте отдельный безопасный проект и резервную копию. Расширение не переносит привязки истории сторонних агентов и не останавливает процессы других окон.
